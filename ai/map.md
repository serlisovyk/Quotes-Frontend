# Repo map

Navigation only: where things live and who owns what. How it works is in the code, why in `ai/decisions/`.

## Repo

- `src/` — all application sources (below); `@/` is its alias. `.next/` is generated by `npm run build` and never edited.
- `public/` — files served as they are: `churchill.jpg` (home page photo), `nav-icon.png` (logo, favicon, link preview).
- `next.config.mjs` — `output: 'standalone'` (the `Dockerfile` needs it), React Compiler, strict mode, `agentRules: false`.
- `jsconfig.json` — the one path alias, `@/*` → `src/*`.
- `vitest.config.js` — Vitest: jsdom, the same alias; `src/tests/mocks/server-only` stands in for `server-only`, `src/tests/setup` cleans up Testing Library.
- `eslint.config.mjs` — flat config: `core-web-vitals`, `API_URL` and `fetch` limited to `src/services`, the naming scheme, Prettier.
- `.husky/pre-commit`, `.lintstagedrc.json` — the pre-commit hook: lint-staged runs ESLint and Prettier on staged files, in chunks.
- `.github/workflows/ci.yml` — CI on every push: lint, format check, tests, build; the build needs the secrets `API_URL`, `SITE_URL`.
- `postcss.config.mjs` — the Tailwind CSS 4 plugin. `.prettierrc`, `.prettierignore` — Prettier.
- `package.json` — scripts `dev`, `build`, `start`, `lint`, `lint:fix`, `format`, `format:check`, `prepare` (installs the hook), `test`, `test:watch`.
- `package-lock.json` — the lockfile (npm).
- `.env.sample`, `.env.production.sample` — tracked templates of the environment; `.env*` is otherwise ignored.
- `Dockerfile`, `Dockerfile.dev`, `docker-compose.yml`, `docker-compose.dev.yml`, `.dockerignore` — see Docker.
- `AGENTS.md` — the entry point for agents; `CLAUDE.md` points to it.
- `ai/` — agent docs: this map, `workflow.md`, `rules/`, `skills/`, `decisions/`, `prompts/`,
  `linear-task-template.md`, and the archive `superpowers/`.
- `.claude/worktrees/` — one git worktree per task when tasks run in parallel; ignored by git.

## Routes (`src/app`)

Only Next.js route files live here; the root layout sits at this level, not in a route group, so an unknown URL gets the 404 page (`ai/decisions/`).
A test sits next to its route file (`page.test.jsx`).

- `layout.jsx` — root layout: fonts (`fonts/`), site metadata, skip link, `AppToasts`, `Header`, `<main>`, `Footer`.
- `globals.css` — Tailwind import, the light and dark `--background` and `--foreground` colors.
- `page.jsx` — `/`: the home page; the card is quote `HOME_QUOTE_ID`, revalidated hourly, left out when missing.
- `random/page.jsx` — `/random`: a random set of quotes, dynamic and uncached.
- `search/page.jsx` — `/search`: reads the query string, searches only when it has params, shows `Pagination`.
- `quotes/[id]/page.jsx` — `/quotes/:id`: one quote with Edit and Delete; an invalid or missing id is a 404 (`notFound()`).
- `quotes/[id]/edit/page.jsx` — `/quotes/:id/edit`: the form bound to `updateQuoteAction`, dynamic, `noindex`, 404 like the quote page.
- `quotes/create/page.jsx` — `/quotes/create`: the form bound to `createQuoteAction`, `noindex`.
- `not-found.jsx` — the 404 page (unknown URL, `notFound()`): heading and a link home.
- `error.jsx` — a failed page load (network error, 5xx): heading and a "Try again" button (`reset`).
- `random/loading.jsx`, `search/loading.jsx` — the spinner while the page loads; quote pages have none (a 404 stays 404).
- `robots.js`, `sitemap.js` — metadata routes (the sitemap lists home, random and search).

## Layers (`src/*`)

Every module has a folder of its own with an `index.js` barrel and its test beside it; `constants/` and `config/` are flat folders with
one barrel. Layers: `ai/rules/architecture.md`; names: `ai/rules/style.md`.

- `services/` — the only code that calls the backend; every file imports `server-only`.
  - `fetcher/` — `fetcher.get`, `post`, `patch`, `delete` over `fetch` and `API_URL`; throws `ApiError` on a bad response.
  - `quotes/` — the endpoint functions (`fetchQuotesResult`, `fetchRandomQuotesResult`, `fetchQuoteById`, `fetchQuoteIfExists`,
    `postQuote`, `patchQuote`, `deleteQuote`) and their cache options.
- `errors/api/` — the `ApiError` class.
- `actions/quote/` — Server Actions `createQuoteAction`, `updateQuoteAction`, `deleteQuoteAction`.
- `utils/` — pure helpers, one folder each.
  - `validation`, `query-string`, `quote-action-state`, `quote-form`, `escape-reg-exp`, `get-single-quote-api-endpoint`,
    `get-displayed-categories` — form and search validation, search params, the shapes of form values and action state, and so on.
  - `create-api-error`, `get-api-error-messages` — turn a failed response or an error into `ApiError` and its messages.
  - `highlight-text`, `render-quote-text` — `.util.jsx` modules that return markup for a search match.
- `constants/` — `api`, `menu` (`MENU_ITEMS`), `quotes`, `routes`, `search` constants (routes, limits, cache seconds, highlight classes).
- `config/` — `home.config.js` (`HOME_QUOTE_ID`), `input-fields.config.js` (form and search field definitions), `site.config.js`
  (site name, description, `SITE_URL`, skip-link classes).
- `components/` — one folder per component, named export, no suffix.
  - Client components (`'use client'`): `app-toasts`, `header`, `menu-items`, `input-field`, `quote-form`, `search-form`,
    `delete-quote-button`, `random-quotes-refresh-button`.
  - Server components: `quote`, `quotes`, `loading-status`, `category-tag`, `category-tags`, `quote-form-fields`,
    `pagination`, `status-message`, `button`, `burger-button`, `loader`, `footer`.
- `hooks/` — none yet; a hook is `use-<name>/use-<name>.js`.
- `tests/` — shared `mocks/` (`server-only`), `setup/` (Vitest setup file) and `utils/` (none yet), each in a folder with a barrel.

## Environment

Copy `.env.sample` to `.env` for local runs; `.env.production.sample` is the production-like set.

- `API_URL` — backend base URL. Server-only: read in `services/fetcher`, never sent to the browser.
- `HOME_QUOTE_ID` — id of the quote on the home page. Server-only, optional: read in `config/home.config.js`.
- `SITE_URL` — public frontend URL for metadata, `robots.js` and `sitemap.js`.
- `PORT` — port of the Next.js server (4000). `HOSTNAME` — `0.0.0.0` in Docker. `NODE_ENV` — mode.
- `CHOKIDAR_USEPOLLING`, `WATCHPACK_POLLING` — file-watcher polling for Docker dev mode.

## Docker

- `Dockerfile` — multi-stage production image on `node:24-alpine` (`npm ci`, `npm run build`, runs the standalone `server.js` as a non-root user).
- `Dockerfile.dev` — dev image on `node:24-alpine`: `npm ci` and `npm run dev`.
- `docker-compose.yml` — runs the published image `serhii5105/quotes-client:latest` with `.env` on port 4000.
- `docker-compose.dev.yml` — builds `Dockerfile.dev`, mounts the project, keeps `node_modules` and `.next` in volumes.
- Production: `docker compose up -d` and `docker compose down`.
- Dev: `docker compose -f docker-compose.dev.yml up --build` and `docker compose -f docker-compose.dev.yml down`.

## What the project does not have

- TypeScript, a state-management or server-state library (native Next.js caching instead), a UI kit.
- Authentication, a database or any backend code: the data comes from the backend API only.
- Middleware files; form and list errors and empty states are rendered inline, only a failed page load reaches `error.jsx`.
- Client-side API calls: the browser never sees `API_URL`.
