# Plan: favorite quotes (MY-384)

Branch `my-384-favorites`. Behavior: `ai/superpowers/specs/2026-11-07-my-384-favorites.md`.

## Author's decisions (2026-11-07)

- Favorites live in `localStorage`, on a `/favorites` page. Nothing is left open for the author.

## Decisions in this plan

- **Storage:** one key `quotes:favorites` (same shape of name as `quotes:theme`), a JSON list of
  snapshots `{ id, text, author, categories }`, newest first. A snapshot, not ids, because the backend's
  rate limit is shared by the whole site and `/favorites` must make no API call. Why: new decision record
  `client-only-favorites`.
- **Layers:** pure utils `parseFavorites` (raw string to a validated list; broken JSON, a wrong shape or a
  bad entry never throws) and `toggleQuoteInFavorites` (adds a snapshot at the front, or removes by id);
  `favorites-storage` is the external store: read, save, subscribe, mirroring `theme-storage`.
- **External store:** `useSyncExternalStore` needs a stable snapshot, so the store caches the parsed list
  by the raw string it came from. Subscribers hear a change event (this tab) and `storage` (other tabs).
  When the storage throws on write, the list lives in memory for the page, so the star still works.
- **Hydration:** the server snapshot is `null`, meaning not loaded. `useFavorites` returns
  `{ favorites, isReady }` from it, so no markup depends on the storage until the client has taken over,
  and the page never shows an empty state to a user who has favorites.
- **Hooks:** `useFavorites` (the list for the page) and `useFavoriteQuote(quote)` (`isFavorite` and
  `toggleFavorite` for one card). The toggle reads the stored list at click time, not the render's copy, so
  two tabs do not overwrite each other.
- **Button:** `QuoteActionButton` gets an optional `isPressed`; without it no `aria-pressed` is rendered, so
  copy and share are unchanged. The star is one more entry of the `QuoteActions` list; its label changes
  with the state («Add to favorites» / «Remove from favorites», as the issue asks), so the list key is the
  icon, not the label, or the button would remount and lose focus. Pressed is a filled star in
  `text-accent-text` (shape plus colour), tokens only.
- **No toast:** the filled star and `aria-pressed` already tell the result, and Sonner would be a second
  announcement for a screen reader (`ai/rules/react.md`); unlike `clipboard-feedback-by-toast`, nothing here
  is invisible.
- **Card on the client:** `Quote`, `Quotes`, `AuthorLink` and `CategoryTags` import nothing server-only, so
  a client component that renders `Quotes` makes them client code with no change and no second card. The
  page `/favorites` stays a server component with metadata and renders the client list `FavoriteQuotes`.
- **Quote page and card** pass `categories` to `QuoteActions`, which now needs the whole snapshot.
- **Read-only:** favorites are local reads, so the star, the page and the menu item stay (`read-only-mode`).
- **Menu:** `Favorites` between `Search` and `Create New`, in the desktop row and the mobile dialog.
- Not added: a cap on the list, export or import, sync with a backend, a count badge.
- Known limit: removing a card on `/favorites` takes it out of the DOM; the browser keeps the sequential
  focus position, no extra focus code.
