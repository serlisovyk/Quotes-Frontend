# Plan: Docker without `.env`, build arguments, image build in CI (MY-378)

Branch `my-378-docker-env`. No observable behavior change for app users, so no spec.

## Author's decisions (2026-11-07)

- CI only builds the image; publishing to Docker Hub stays manual.

## Decisions in this plan

- **Env files never enter an image.** `.dockerignore` excludes `.env*` except `*.sample`, so `COPY . .`
  cannot bring them into the build and Next cannot copy them into `.next/standalone`.
- **Build-time values are build arguments.** `SITE_URL` (`metadataBase`) and `HOME_QUOTE_ID` are read
  during `npm run build`: `ARG SITE_URL` and `ARG HOME_QUOTE_ID` in the builder stage only.
- **`API_URL` is a build argument too, not only a runtime variable (deviates from the issue text).** The
  home page is prerendered at build and fetches its quote then: a trial build without `API_URL` produced a
  home page with no quote card, with it the card (`/quotes/1` link) is there. A baked-in `.env` used to
  hide this. At run time `API_URL` still comes from `env_file` / `--env-file`.
  The ARGs live in the builder stage, which is not shipped; they are not in the final image config.
- **Dev stays as it is.** `Dockerfile.dev` copies the project (`.dockerignore` keeps `.env*` out of that
  build context too) and `docker-compose.dev.yml` keeps `env_file: ./.env` at run time, so no env file is
  baked into the dev image either.
- **`.dockerignore` also drops what a build never needs:** `.git`, `.github`, `.husky`, `.claude`, `ai`,
  `*.md`, test files and `src/tests`, and the Dockerfiles and compose files.
- **CI job `docker`** (as on the backend): `docker build` on every push, no push to a registry, with
  `--build-arg API_URL`, `SITE_URL` and `HOME_QUOTE_ID` from GitHub Secrets (`HOME_QUOTE_ID` optional).
- A decision record: env files never enter an image, build-time values are build arguments.
