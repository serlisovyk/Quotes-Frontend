# Plan: honest test coverage and the missing tests (MY-242)

Branch `my-242-coverage`. Linear issue MY-242, milestone Рефакторинг, project Quotes. Tests and
tooling only, no behavior change, so there is no spec. Runs alone (touches tests across the repo).

## Author's decisions (2026-11-07)

- Coverage with `@vitest/coverage-v8`, measured over all of `src/` (`coverage.include`).
- Thresholds per metric, just below the measured value after the new tests; from now on they only go up.
- Scripts: `test:coverage` (`vitest run --coverage`); `npm test` stays without coverage. CI runs
  `test:coverage` instead of `npm test` and fails below the thresholds.
- Add `@testing-library/user-event` and `@testing-library/jest-dom` (`@testing-library/jest-dom/vitest`
  through `src/tests/setup`); both are used in new and touched tests, untouched tests are not rewritten.
- A short decision record; `ai/rules/testing.md` updated.

## Decisions made in this plan

- **Exclusions** (only what has no behavior to test, `ai/rules/testing.md` "What not to test by
  default"): barrel `index.js` files, `src/tests/**`, test files, and `src/app/robots.js` (a literal
  object, named in that list). Not excluded: constants and config (they are small and already fully
  covered by import, excluding them would hide a later real branch), route `loading.jsx` re-exports
  (covered through `LoadingStatus`), `sitemap.js` (it already has a test).
- **Reporters:** `text` and `html`; `coverage/` is already in `.gitignore`.
- **Thresholds** are set after the tests are written, floored to the integer below the measured value.
- **user-event:** `userEvent.setup()` per test; `fireEvent` stays only in untouched tests.

5. `docs:` testing rules, `AGENTS.md`, `ai/map.md`, README, decision record + index.

the fix as `fix: ...`, and it is listed in the report.
