# Plan: Husky, lint-staged and CI (MY-221)

Branch `my-221-husky-ci`. Linear issue MY-221, milestone Фундамент, project Quotes. Tooling and docs
only, no behavior change and no change in `app/`, so there is no spec.

## Author's decisions (2026-11-06)

- ESLint gets exactly two architecture rules: `process.env.API_URL` may only be read in the services
  folder, and the global `fetch` may only be called there. Kebab-case and named exports stay with MY-238.
- CI runs `npm run build` with the real `API_URL` and `SITE_URL` from GitHub Secrets; the author adds the
  two secrets by hand.
- `eslint-config-prettier` stays last and the flat config keeps its shape (MY-219).

## Changes

- `eslint.config.mjs`: constants for the services folder, the messages and the `fetch` owners at the top;
  one block for all sources outside `app/_services/**` with `no-restricted-globals` (`fetch`),
  `no-restricted-properties` (`window`, `globalThis`, `self`, `global` `.fetch`) and
  `no-restricted-syntax` (`process.env.API_URL`, also computed and destructured). Tests of the services
  sit inside the folder and mock `global.fetch`, so they need no exception. `prettier` stays last.
- `package.json`: `husky` and `lint-staged` in `devDependencies`; script `prepare: husky` after
  `format:check`, as in the standard's table.
- `.husky/pre-commit`: `npx lint-staged`.
- `.lintstagedrc.json`: `*.{js,jsx,mjs}` runs `eslint --fix` and `prettier --write`; `*.{css,json,md,yml}`
  runs `prettier --write`.
- `.github/workflows/ci.yml`: every push, `HUSKY: 0`, Node 24, `cache: npm`, `npm ci`, `lint`,
  `format:check`, `test`, `build` with `API_URL` and `SITE_URL` from secrets on the build step.
