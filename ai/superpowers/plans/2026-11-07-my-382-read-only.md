# Plan: read-only mode (MY-382)

Branch `my-382-read-only`. Behavior: `ai/superpowers/specs/2026-11-07-my-382-read-only.md`. Why: the
decision record `2026-11-07-read-only-mode.md` written by this task.

## Author's decisions (2026-11-07)

- Read-only mode by a server environment flag, no backend change.
- The backend's shared per-IP request limit stays a known risk, recorded in the decision.

## Decisions in this plan

- **Name:** `READ_ONLY`, server-only, never `NEXT_PUBLIC_` (`api-url-server-only`).
- **Parsing:** `parseReadOnly(value)` util: true only for `true`, trimmed and case-insensitive.
  `src/config/read-only.config.js` exports `IS_READ_ONLY = parseReadOnly(process.env.READ_ONLY)`, like
  `HOME_QUOTE_ID`.
- **Message:** `READ_ONLY_MESSAGE` in the quotes constants.
- **Menu:** `MENU_ITEMS` marks «Create New» with `isWrite: true`; `MenuItems` takes `isReadOnly` and drops
  such items. `Header` takes `isReadOnly` and passes it to both `MenuItems`; the server layout passes
  `IS_READ_ONLY` (the only layout change).
- **Pages:** the quote page renders the button group only when not read-only; the create and edit pages
  call `notFound()` first. The delete button's internals are not touched (another task owns them).
- **Actions:** each action returns an error state first thing, before parsing or the API.
- **Build or run time:** the layout is shared with the prerendered home page, so the flag is read when a
  page is rendered. Verify on a production build, flag off and on, whether the home HTML follows the build
  or the run environment, and record the result in the decision and, if it is build time, in the
  `Dockerfile` (`ARG`) and CI (`--build-arg`) per `no-env-files-in-image`.
- Tests mock `@/config`; none depends on `.env`.
