# Plan: tests move from Jest to Vitest (MY-340)

Branch `my-340-vitest`. Linear issue MY-340, milestone Рефакторинг, project Quotes. Tooling and tests
only, no behavior change, so there is no spec: the existing 164 tests are the safety net and their
expectations do not change.

## Author's decisions (2026-11-07)

- Vitest; an explicit `import { ... } from 'vitest'` in every test file, no `globals`.
- `jsdom`, `clearMocks: true`, `restoreMocks: true`, `include: ['src/**/*.test.{js,jsx}']`.
- `npm test` is `vitest run`, `npm run test:watch` is `vitest`.
- Runs alone, before the next batch of tasks.

## Decisions made in this plan

- **JSX: no React plugin.** Vitest 5 on Vite 8 transforms JSX with Oxc, whose default runtime is already
  automatic, so `@vitejs/plugin-react` is not installed. The React Compiler stays a Next.js concern.
- **Alias** `@` → `src` and `server-only` → `src/tests/mocks/server-only` through `resolve.alias`.
- **Cleanup.** Without `globals`, Testing Library does not register its automatic `cleanup`; a setup
  file (`src/tests/setup`) calls it in `afterEach`. Without it 20 tests fail on leftover DOM.
- **No `.env`.** Vitest does not read it, which is the point: tests never depend on it.
- **Dependencies.** Remove `jest`, `jest-environment-jsdom`; add `vitest` (`^5.1.0`) and `jsdom`.
  `@testing-library/jest-dom` stays untouched (a later task decides on it).

## Changes

- `vitest.config.js` replaces `jest.config.js`; `package.json` scripts and devDependencies.
- Every `*.test.js(x)`: `jest.*` becomes `vi.*`, `jest.requireActual` becomes `await vi.importActual`
  (async factory), a default-export mock returns `{ default }`, a variable a `vi.mock` factory reads
  comes from `vi.hoisted`, the Vitest names are imported explicitly.
- ESLint, lint-staged, `.prettierignore`, `.gitignore`, CI: checked, they hold no Jest reference.
